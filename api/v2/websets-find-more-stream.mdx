Streams state, strategy, and item changes for one specific Find More job. Requires `websets:read`.

<Note>
  The existing `GET /api/v2/websets/{webset_id}/find-more/stream` endpoint remains supported with the same parameters, response fields, and permissions. Both URLs execute the same operation.
</Note>

## At a glance

|  |  |
| --- | --- |
| Method | `GET` |
| Path | `https://revor.ai/api/v2/prospect-lists/\{webset_id\}/expand/stream` |
| Permission | `websets:read` |

## Query parameters

<ParamField query="job_id" type="string" required>
  `item.id` returned by Find More.
</ParamField>

<ParamField query="cursor" type="number">
  Paired with revision. `stream_cursor` captured before starting Find More.
</ParamField>

<ParamField query="items_revision" type="number">
  Paired with cursor. `items_revision` captured before starting Find More.
</ParamField>

<ParamField query="match" default="qualified" type="string">
  Defaults to `qualified`.
</ParamField>

<ParamField query="detail" default="compact" type="string">
  `compact`, `standard`, or `full`; defaults to `compact`. Use the same mode for the snapshot and stream.
</ParamField>

Bind the stream to the current `job_id`. The server waits until it observes that job's new discovery run and will not treat the previous run's stale `completed` state as completion.

## Request example

```bash cURL
curl -N "https://revor.ai/api/v2/prospect-lists/WEBSET_ID/expand/stream?job_id=JOB_ID&cursor=289&items_revision=18&match=qualified" \
  -H "Authorization: Bearer sk-revor-REPLACE_ME" \
  -H "Accept: text/event-stream"
```

## Events

This endpoint includes the [Items SSE](/api/v2/websets-items-stream) events `ready`, `webset.state`, `webset.strategy`, `items.changed`, `reset`, `complete`, `reconnect`, and `error`, plus the following events.

`ready`, `webset.state`, and `complete` include `progress` and `failure`. Item detail modes, truncation, and checkpoint recovery follow the [Items SSE](/api/v2/websets-items-stream) contract.

### `find_more.state`

```json find_more.state
{
  "webset_id": "webset-uuid",
  "job_id": "job-uuid",
  "job_status": "running",
  "run_observed": true
}
```

`run_observed=true` means the new discovery run for this Find More job has been observed.

### `find_more.failed`

Sent when the job fails or is cancelled before it starts a new run; the stream then closes. If the new run already started, use `items.changed` and `complete` as the final outcome.

```json find_more.failed
{
  "webset_id": "webset-uuid",
  "job_id": "job-uuid",
  "job_status": "failed",
  "error_code": "webset_find_more_failed"
}
```

<Note>
  `ready`, `complete`, and `reconnect` also include `find_more_job_id`. End normally on `complete`. On `reset`, fetch a complete Items snapshot again.
</Note>
