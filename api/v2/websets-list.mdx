Page through Revor AI prospect lists owned by the API key's user. Requires `websets:read`.

<Note>
  The existing `GET /api/v2/websets` endpoint remains supported with the same parameters, response fields, and permissions. Both URLs execute the same operation.
</Note>

## At a glance

|  |  |
| --- | --- |
| Method | `GET` |
| Path | `https://revor.ai/api/v2/prospect-lists` |
| Permission | `websets:read` |

## Request example

```bash cURL
curl --get \
  --url "https://revor.ai/api/v2/prospect-lists" \
  --header "Authorization: Bearer sk-revor-REPLACE_ME" \
  --data-urlencode "limit=20" \
  --data-urlencode "target_kind=company"
```

## Query parameters

<ParamField query="limit" default="20" type="integer">
  Number of lists per page. Accepts values from `1` to `100`.
</ParamField>

<ParamField query="target_kind" type="string">
  Filter by `company` or `person`. Omit this parameter to return both kinds.
</ParamField>

<ParamField query="cursor" type="string">
  Use the previous page's `next_cursor` unchanged. Do not parse or modify it.
</ParamField>

## Pagination

When `has_more=true`, pass `next_cursor` unchanged to the next request. This is a REST pagination cursor, not the SSE `stream_cursor`.

<Accordion title="Searches and imported lists">
  Lists include Revor searches and imported CSV/XLSX tables. `source` identifies `revor`, `tabular_import`, or historical `csv_import`; `total_items` is the stored row count. Imports use `importing` while processing and have null search-goal and verification statistics.
</Accordion>
